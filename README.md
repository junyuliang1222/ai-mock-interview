# Resume Interview — Claude Code 模拟面试 Skill

一个通用的模拟面试技能，让 Claude 成为你的专属面试官。贴上简历，选择难度和风格，即可开始一轮轮真实模拟面试。

## 功能特点

- **四档难度**：日常实习生 / 暑期实习生 / 校招生 / 研究生入学面试，不同档位的追问深度、语感、考察侧重完全不同
- **三种面试风格**：技术深挖 / 综合面试 / 岗位自适应（自动根据简历判断岗位类型）
- **可选岗位 JD**：提供 JD 后面试会贴合职位要求提问，JD 与简历的落差也会在面试中点出
- **真实面试口吻**：提问自然多样（直接技术问、场景假设、挑刺质疑、开放性、连续假设等），不机械套模板
- **追问机制**：5 Whys 自然融入，根据回答质量灵活决定追问层数
- **结构化反馈**：全部提问结束后，以 STAR + CARL 框架 + 能力素质模型给出分维度反馈和改进建议
- **通用岗位**：不绑定特定领域，技术岗（前端/后端/数据）、业务岗（产品/运营）、创作岗（设计）、研究岗（学术）均适用

## 使用方式

在 Claude Code 中，输入以下任一关键词即可触发：

- "帮我模拟面试"
- "来一场mock interview"
- "面试练习"
- "帮我看简历并进行面试提问"
- "面经练习"
- "面试教练"

触发后，Skill 会依次引导你完成：

1. **贴简历** — 把简历文本贴进来
2. **岗位 JD**（可选）— 有的话贴进来，面试会贴合 JD 要求
3. **选风格** — 技术深挖 / 综合面试 / 岗位自适应
4. **选难度** — 日常实习生 / 暑期实习生 / 校招生 / 研究生入学面试

然后面试开始，一轮轮提问 → 回答 → 追问 → 下一题。全部结束后给出总结反馈。

## 难度档位对照

| | 日常实习 | 暑期实习 | 校招 | 研究生入学 |
|------|:--:|:--:|:--:|:--:|
| 核心问题 | 学得快不快？ | 值得培养吗？ | 能直接干活吗？ | 适合做研究吗？ |
| 深度天花板 | 基础 + 学习力 | 接近校招 | 追问到底 | 理论深挖 |
| CARL 侧重 | L（怎么学的） | A/R | 完整 STAR | L + 方法论 |
| 追问力度 | 1-2 层 | 2-3 层 | 3-5 层 | 理论深度 |
| 压力感 | 友善 | 偏严留余地 | 严格挑剔 | 学术探讨 |

## 反馈框架

面试结束后，从以下维度给出结构化反馈：

### STAR/CARL 评估

| 维度 | 评估内容 |
|------|------|
| S (Situation) | 背景和角色是否交代清楚 |
| T (Task) | 要解决的问题是否明确 |
| A (Action) | 行动过程是否具体、有细节 |
| R (Result) | 成果是否有量化或定性说明 |
| C (Context) | 是否说明了限制条件、资源约束 |
| L (Learning) | 是否总结了收获和反思 |

### 能力素质模型（以技术岗为例）

技术基础 · 系统设计/架构 sense · 问题解决能力 · 沟通表达 · 学习能力 · 项目经验深度

每个维度 1-5 分，附一句话理由。不打综合总分，不做通过/不通过结论。

## 示例

```
面试官：你在简历里写做了一个 API 网关。跟我说说，这个网关的限流是怎么做的？

候选人：我用了令牌桶算法，每个请求先去拿令牌...

面试官：（追问）为什么选令牌桶而不是漏桶或者固定窗口？当时对比过哪些方案？

候选人：令牌桶能处理突发流量，固定窗口会有临界问题...

面试官：（追问）那令牌桶有什么缺点？什么场景下会撑不住？

候选人：如果多实例部署的话，单机限流就不太准了...

面试官：（质疑）那你多实例之间怎么同步令牌？有没有更简单的方案？
```

## 技能边界

- 不保存或记录面试内容，面试仅在当前对话中进行
- 反馈基于 STAR/CARL 框架的结构化观察，不是权威评价
- 模拟通用面试场景，不针对特定公司
- 简历过于简短（如只有 2-3 行）时，会建议提供更详细内容后重试
